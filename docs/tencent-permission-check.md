# 腾讯文档只读权限检查

## 入口与边界

集团填报 → 设置 → 网页配置 →「检查填写位置权限」。填写完整工作表名称和单元格地址后点击「检查位置」。请求沿用 `tencentSheet.sessionVerify`，经既有 Electron IPC、Bridge、.NET Sidecar、Node Worker 和唯一受管 Edge PersistentContext 完成。

请求新增可选 `permissionTargets` 和 `refreshPermissions`，没有第二套会话操作。每个目标指定 `sheetId` 或 `sheetName`、`address`，可附业务项 `label`。同时指定 ID 和名称时必须匹配。界面采用工作表名称；后端也接受明确的工作表 ID，不把当前鼠标选区当成目标。

```json
{
  "documentUrl": "https://docs.qq.com/sheet/example",
  "permissionTargets": [
    { "sheetName": "示例月报", "address": "B9", "label": "示例业务项" }
  ],
  "refreshPermissions": true
}
```

界面复用现有 Input、Label、Button、Badge、Spinner 和连接组件，保留文档连接、登录、二维码及其他会话操作。输入变化清除旧目标结果；检查过期后显示需重新核验。业务字段配置、执行规则的既有 Mock 边界不变。

本功能只检查前置条件。`eligible` 不表示服务端保证写入、保存或云端持久化成功。未接入正式填报提交入口，没有自动触发填报、改权限、保存或扫码。

## 四种独立事实

| 事实 | 输出 | 依据 |
| --- | --- | --- |
| 账号认证 | 既有 `authenticated / required / unknown` | 真实 `user_info` 业务状态码及既有有效期、只读复核 |
| 文档编辑权限 | `editable / read-only / unknown` | 双页面权限字段严格一致、权限未过期 |
| 目标保护 | `protected / unprotected / unknown` | 已初始化且稳定的工作簿范围模型、明确工作表和原生坐标语义 |
| 填写资格 | `eligible / denied / unknown` | 认证、文档、模型、全部命中范围的当前权限与额外限制 |

文档主字段为 `basicClientVars.authInfo.attribute.canEdit`，仅接受布尔值；辅助字段为 `clientVars.privilegeAttribute.can_edit`，仅接受布尔值或数值 0/1。缺失、冲突、过期或未识别表示均为 unknown。当前真实页面的 `privilegeExpire` 原始值为数值 0；P2 报告将它归一化为 false，本实现严格兼容这两种未过期表示，不接受字符串。

账号身份仅在 Worker 内使用真实响应中已核对的身份字段生成私有摘要，以识别已确认账号的变化。身份值和摘要均不进入快照、Bridge、日志或配置。没有身份关联证据时，不输出目标 eligible。XSRF 沿用原模块的自然观察、当前 Cookie 核对及只读认证请求，不硬编码、不落盘。

## 初始化与范围模型

检查综合当前页面身份、`clientVars.dataIniting === false`、活动工作表存在及 `getIsInitialized() === true`、双权限字段完整、管理器只读 API 和查询结果的一致性，再经过有限稳定观察。目标工作表也必须已经初始化，坐标必须处于它的行列边界内。

未加载的工作表返回 unknown；本轮不通过未验证的接口自动切换或加载其他工作表。

空数组不是单独的就绪依据，也不要求保护数量大于零。模型完整时的合法零保护区域可以完成检查；初始化空模型保持 unknown。

复用 `workbookRangeManager` 的四个只读查询。按工作表查询传入 `(sheetId, type)`。保护类型统一为 `Protected = 3`，已对照本轮实际加载平台脚本中的类型枚举；其他已知范围类型不冒充保护范围。未知类型、未识别坐标、负索引、无有效工作表关联等情况不放行。

目标点由原生 Range 克隆后明确赋值，使用原生 `contains / isInvalid / isAll / isRow / isCol` 语义。当前选区只可能提供空模型下的原生坐标类型，绝不提供目标位置。匹配所有重叠范围；不取第一条就放行。未保护目标还必须通过原生编辑限制检查，不能仅由“没匹配到范围”获得资格。

## 自然区域响应及证据生命周期

区域服务观察同时检查受管页面的来源、URL 或请求体中的服务特征，不绑定唯一传输 URL。仅处理自然产生的用户区域权限响应，严格检查 HTTP 状态、`retcode` 及其他已出现业务码、数据结构、`isOwner` 和区域字段。不主动请求区域权限、不修改权限。

当前已验证的禁止样本为 `isOwner=false, rangePrivilege=1`。其他所有者组合、值 2 或其他未验证值均不映射为允许。保护区域存在但未取得对应有效证据时保持 unknown；重叠区域中任一已确认只读即拒绝，其他组合不会因一条记录而放行。

| 证据 | 作用域与失效规则 |
| --- | --- |
| 认证 | Context 内现有 30 秒策略；服务端身份、认证状态或已知 XSRF 变化更新账号代次；关闭销毁 |
| 文档、区域模型 | 当前文档、Context generation、page generation、页面 realm、权限修订和模型指纹；15 秒策略 |
| 区域服务端权限 | 当前账号代次、文档、Page 代次、请求顺序、区域 ID；15 秒，不能跨文档或账号复用 |
| 目标结果 | 包含独立文档/模型/区域证据来源、观察时间及作用域；总有效期不超过其依赖证据的最早期限 |

真实导航请求、文档切换、相关 Frame 重建/脱离、Page 重建及 Context 关闭使旧页面证据失效。同一文档的地址整理不重复计为新页面。权限事件和模型变化使旧模型或区域快照失效，新权限请求使旧区域响应失效；迟到响应不能恢复旧代次。

`SessionStatus` 读取时核对页面代次、页面内修订/模型和期限；需要时返回未核验。`SessionVerify` 每次重新读取文档与模型，初始化等待最多 6 秒；需要保护证据时在剩余预算内最多额外观察 1.8 秒。认证仍使用原有 8 秒只读探测和频率限制；外层 .NET 操作截止时间为 45 秒。所有等待均有界。明确重新检查可刷新当前 Headless 页面取得自然响应；人工页面占用时不导航、刷新或接管它。

## 测试与已验证边界

- `check-permissions.cjs`：纯逻辑和 Mock 模型，覆盖双字段正反、冲突/缺失、初始化和合法空模型、重叠、未知类型/索引、整行/整列/整表模型、响应业务错误/缺失、文档隔离、事件、时效、导航/账号代次和超时。特殊范围测试为模型验证，不宣称已完成腾讯真实正反样本。
- `check-authentication.cjs`：既有认证回归及私有服务端身份变化、不泄漏身份值。
- `check-session.cjs --browser`：真实 Headless Edge，但页面和主动认证请求都完全拦截，使用合成资料；不需要真实生产文档。
- React：已有设置和连接回归、新增目标权限交互测试，包括并发、错误、配置变更、输入变更、过期与卸载。
- .NET：既有会话服务、Worker 往返测试中增加目标输入验证和结构化结果传递；保持现有操作白名单。

本轮真实只读复测已观察到：文档可编辑、完整加载模型，受保护回归目标被服务端只读证据拒绝，未保护目标满足前置条件；首次、重复、显式刷新、重载及 Page 重建得到一致结果。Context 复用、页面失效和正常关闭均已观察。业务样本标识只保留在本机忽略目录，不进入源代码或本文。

真实只读文档负样本、权限撤销/实际账号切换、可编辑保护区域、所有者例外、特殊范围和真实 iframe 重建等尚未全部完成现场正反验证。上述未验证权限不会据此开放。完整自动化、发布到 Development 的结果及现场链路验收见 `STATUS.md` 和本机 `artifacts/p3-permissions`；自动化不代替用户人工视觉验收。
