# 腾讯文档模块审查与精简

审查基线：`e578ed7`。本次目标：网页控件和具体业务位置都归当前任务，按并列板块配置；保留前台、后台和定时执行能力。

## 已处理的问题

| 问题 | 影响 | 处理 |
| --- | --- | --- |
| 独立共享适配库与任务内业务位置分层冲突 | 录制必须先创建另一种配置；更新控件会影响多个任务 | 删除适配库写入和选择管理，改为任务的 `webControls`，旧引用仅作迁移输入 |
| 新建与编辑页重复连接、录制、兼容点选 | 配置流程重复、入口含义不清 | 新建只填链接；文档、网页控件、业务位置、执行规则同级 |
| `TencentSheetClient.pick/discover` 与 `site-adapter` 双实现 | 旧实现允许 nth-of-type、DOM 序号与预设选择器兜底，和新版定位原则冲突 | 删除旧录制器和探测代码；只保留读取已保存旧定位的执行兼容 |
| 正式桥接暴露 Demo defaults、captureSheet | 无页面调用，正式模块仍可读取实验配置 | 删除路由及实现；正式 core 删除 simulate 和浏览器 Demo 导出 |
| 桥接白名单与实际路由不一致 | 后台测试、关闭浏览器会被入口拒绝，已删接口仍在白名单 | 补齐 backgroundTest/close 并移除旧接口，增加入口回归断言 |
| 自定义新任务也混入固定旧业务默认值 | 不相关公司、园区、行列及月份名称进入新配置 | 仅 `legacyKey` 或无字段列表的旧配置使用这些默认值 |
| 前台写入凭据未绑定 task id | 两个配置完全相同的任务可消费同一预览凭据 | inspect/write 显式绑定任务；控件测试凭据也绑定任务、配置签名和 URL |
| 切换任务保留旧页面状态 | 数值、日期或预览仍来自上一任务，异步旧加载还可能覆盖新页面 | 切换时清空并忽略已退出任务的加载结果 |
| 所有失败记录均阻止同日定时执行 | Notion 取数失败也会让后续执行时刻一直跳过 | 区分 fetch/check 与 write 阶段；写入不确定仍禁止自动重复 |
| 互斥仅保护落盘，没有旧配置检测 | 等待网页操作期间，旧请求可能覆盖新配置 | 配置修订号在存储提交时核对，前端整份保存携带原修订号 |
| 旧 CSS 与业务文案残留 | 已删除结构的样式仍保留，通用任务被描述成固定生产业务 | 删除失去引用的样式并更新模块说明 |

## 有意保留

- `TencentSheetClient` 的日期/文字锚点、空值检查、逐格回读与刷新保存确认：这是写入安全边界，不属于无用代码。
- 旧 `adapter`、`legacyKey`、`dateMode` 的读取：已有任务依赖它们。只删新建/编辑入口，不让旧任务被迫重录全部业务位置。
- Handler、Notion 取数服务、stdio worker、浏览器与 DOM 适配器各自职责：没有再建通用 Workflow、额外服务层或新依赖。
- 单任务只匹配一个工作表；字段可横纵混排，但不支持跨多个 Sheet、任意脚本或不规则日期布局。此次不扩大业务模型。
- 专用登录 profile 串行使用、最近 100 条记录、环境调度默认关闭：继续作为现阶段明确边界。

## 验收边界

代码/本地替身验证包括：任务内控件隔离、无预设新任务、旧位置兼容、凭据跨任务拒绝、同级页面、日期边界、取数失败与写入待确认区分，以及真实 localhost DOM 的填写/保存回读。

本次不访问真实共享文档，不启用 Windows 计划任务，不更改 Production 数据或发布目录。真实登录与在线保存仍需用户测试。
