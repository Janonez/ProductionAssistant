# 腾讯文档填报（Development）

入口：自动化任务 → 新建任务 → 腾讯文档填报。仅在 Development 注册 Handler，Production 桥接拒绝访问。本模块不依赖实验 Demo 的配置或模拟写入。

## 当前配置层级

一个填报任务拥有以下并列配置：

- 文档：分享链接、工作表名称与月份匹配规则。
- 网页控件：`config.webControls`，包括 Sheet 标签集合、单元格名称框、内容编辑区。通过 `TencentWebControls` 录制、测试后保存。
- 业务字段与填写位置：`config.fields` 保存名称、单位、Notion 绑定；`config.rules` 以稳定字段 id 保存位置规则、日期锚点和文字锚点。
- 执行规则：`config.businessDateRule` 决定数据日期；`config.executionSchedule` 决定执行星期和时刻。

页面中这些配置是同级板块。新建时只填写链接，控件录制不再是创建任务的前置流程。不再建立、选择、重命名或更新跨任务共享适配。网页控件不包含具体业务位置，业务位置示范需要先有可用的网页控件。

## 使用

1. 新建任务并填写链接。在文档板块点击“扫码登录”，前端弹窗默认使用企业微信。已有登录状态会复用；首次按官方页面提示阅读并同意协议，再扫码并在手机确认。控件录制和位置示范仍使用“打开文档”进入专用浏览器。
2. 在“网页控件”板块录制三个控件，测试通过后保存到当前任务。保存会废弃旧取数/位置预览；不会修改其他任务。
3. “识别并检查”只检查已保存的定位并读取 Sheet 名称，不猜测 DOM 序号或自动生成候选定位。选择工作表后保存任务配置。
4. 在“业务字段与填写位置”中新增业务名称及单位，选择现有 Notion 数据库、数值字段、日期范围或真实 View，然后示范业务位置。
5. 配置执行规则并保存。保存规则不会自动启用定时。
6. 前台测试：取数 → 核对来源/日期/数值 → 检查位置 → 一次性确认写入。后台自动测试：一次触发重新取数、检查、真实写入及保存确认。

业务位置示范：选择同月两个日期，分别记录目标格，再记录第一个日期的日期表头和固定文字标志。程序验证第二、第三个日期，并选中第三个预测位置；用户确认当前选区正确后保存。每个字段可独立横向或纵向排列，同一任务仍只面向一个按名称匹配的工作表。

## 数据与日期

- 新任务字段为空，不注入下料、装焊、公司、园区、行列或月份名称默认值。
- `TencentSheetNotionService` 复用现有 `IDatabaseQueryProvider` 与全局凭据，字段只保存引用。日期范围或 View 相同的查询在一次取数中复用；View 沿用数据库原筛选。
- 空记录、空值和非数字结果报错，不自动补 0；真实数值 0 可写。支持 number 及实际数字结果的 formula/rollup。
- 业务日期可为相对执行当天的整数偏移或固定日期。执行当天按北京时间计算；临时补填日期仅影响当前操作。
- 一次取数后日期固定，后续月份匹配、位置计算、检查、写入沿用同一天，不跨午夜重算。
- 取数快照绑定任务、完整配置及业务日期，5 分钟有效；写入预览另外绑定任务、配置、位置、数值，2 分钟有效且一次消费。切换任务、修改配置或重录控件会清空页面旧预览。

## 网页操作与安全边界

- 只有 `site-adapter.cjs` 的录制器产生新控件规则：悬停高亮，点击记录而不执行原动作。支持稳定 CSS、role/name、placeholder 及唯一 iframe 路径，不按坐标或 DOM 序号兜底。
- Sheet 录制识别同类集合，测试时切换两个标签再切回以学习唯一选中状态。每次点击后等待状态规则明确指向目标且稳定，再进行下一次切换；不再固定等待 250 毫秒后直接采样。尚无已知规则且初次点击不改变状态时，只把它作为临时基线，仍须通过后续往返验证。支持 class、ARIA/data 或可区分的样式。按名称精确匹配，不选择相近月份。
- 单次状态学习最多等待 10 秒；超时停止后续点击，不声称已切回。正式填写等待 Sheet 时也会反复重新解析当前选中标签，覆盖异步切换及纯样式定位。
- 控件测试包含切换 Sheet、名称框定位 J9、编辑区可用及地址/内容不变等 6 项，不输入业务值。测试凭据绑定任务、配置签名、URL 和控件，10 分钟且一次消费；不能跨任务保存。
- 后台打开页面后，先等待录制的标签集合与目标名称出现；即使尚无选中标识也可按唯一名称点击一次，再等待目标的选中标识。确认目标 Sheet 后才等待名称框/编辑区并读取业务位置。标签容器、集合、目标名称和选中标识均有独立超时原因；保存控件、识别页面和位置示范共用就绪检查。
- 名称框与编辑区在后台新开页面、切换 Sheet 和回读时按配置超时等待就绪：要求唯一、可见、可编辑，名称框还须显示有效单元格地址。只重试控件读取，不重试输入或提交；超时分别说明未出现、重复、不可编辑或地址未就绪，登录失效立即停止。
- `TencentSheetClient` 同时服务前台和后台。写入前校验日期/项目标志及所有目标空值，输入前再核对地址和空值，输入后 Enter 提交并离开回读。任何非空值（包括 0 和相同数字）都阻止覆盖。
- 最终保存确认沿用状态观察、延迟刷新和回读。刷新后在 30 秒期限内等待名称框、编辑区、选中 Sheet 恢复；只重试控件发现，不重复输入。保存结果不确定时保留错误和已提交地址。
- 后台关闭同一 worker 的前台浏览器，以专用 profile 打开无头 Edge，结束后关闭；保留登录状态。其他进程占用 profile 时失败，不复制凭据或抢占浏览器。
- 页面关闭、登录失效、模板/权限/非空冲突均停止。仅对明确的读取网络瞬断重试两次；不重跑整个写入。

## 前端扫码登录

- `TencentLoginDialog` 使用正式桥接 `tencentSheet.login`，默认企业微信。读取官方登录页面的二维码图片与状态，不把 Cookie、登录回调地址或整页 HTML 发给前端。
- `login.cjs` 复用原有 profile，在后台浏览器中打开目标文档。官方协议尚未确认时先显示协议入口，由用户点击“同意协议并继续”；协议链接通过限定为两条官方地址的宿主入口打开。
- 登录成功同时要求目标文档地址、账号区和表格标签证据。匿名可查看的表格、二维码消失或手机扫码本身均不算成功。用户完成后保留浏览器供“识别并检查”使用；录制与示范可再打开前台浏览器。
- 轮询串行，二维码过期、错误或取消时清除前端图片。会话绑定任务、文档地址和随机标识；关闭与路由卸载会排队取消，即使任务被删除仍能清理。活动扫码期间同一 worker 拒绝其他文档操作。会话有效期为 10 分钟，准备二维码连续超过 45 秒时允许刷新重试。
- 兼容入口“打开文档”仍保留，可在专用浏览器中处理官方额外验证。扫码与确认不修改业务单元格，不变更任务配置或既有运行记录。

## 定时与记录

- 前台手动、后台自动测试、Windows 定时共用 Handler 和写入路径。所有执行均要求每个字段都有完整 Notion 绑定及位置示范，数值仅来自本次取数快照。
- Windows 任务名含 Development，命令显式传环境、任务类型和任务 id。采用当前用户 InteractiveToken、有限权限、IgnoreNew；须电脑开机且 Windows 用户已登录。不开机补跑、不设置自动重试。
- 每个执行时刻使用一个每周 CalendarTrigger，星期与时间可组合。默认 Development 的 `Scheduler.Enabled=false`；只有环境开放且当前配置后台测试成功后，任务开关才允许启用，启用不会立即执行。
- 后台取数前保存 `phase=fetch` 记录；任何实际文档填写前保存 `phase=write` 记录。已写入或可能已写入的同一业务日期阻止定时再次执行；仅取数/检查失败允许下一个正常时刻重试。没有阶段信息的旧失败记录保守视作待确认。
- 运行记录保留最近 100 条，记录来源、日期、实际取数和错误。非空保护始终生效，历史截断不允许覆盖已有值。
- 跨进程执行锁避免并行填报，浏览器操作有独立锁。存储写入使用互斥与原子替换，保留运行记录；`configRevision` 阻止旧异步操作覆盖新配置。前端保存携带读取时的修订号。
- 已启用时先停用再修改配置。停用先保存禁用状态再移除系统任务；移除失败仍阻止后续实际执行。

## 配置重置（2026-09-14）

按用户要求，删除旧设计及全部兼容路径。仅支持任务内 `webControls`、自定义 `fields/rules` 和 `businessDateRule`；不迁移共享适配库，不读取旧选择器、固定四项业务、行列默认值或 `dateMode`，不提供手动数值输入。

Development 的腾讯文档任务配置及其中的运行记录清空，旧共享控件库删除；重新创建任务、录制控件并配置业务。专用浏览器登录状态保留，其他模块数据不受影响。

## 验证

- .NET：配置隔离、修订保护、日期边界、Notion 查询/汇总、定时 XML、失败阶段与去重判定。
- 前端：同级板块、任务内录制、测试后保存、切换任务清空旧状态、前台/后台入口。
- `tests/tencent-sheet/check-rules.cjs`：规则推导、年月边界、空白新任务、必需的位置规则。
- `check-protocol.cjs`、`check-site-protocol.cjs`、`check-background.cjs`：任务绑定、一次性凭据、后台冲突/失败不重复写。
- `check-site-adapter.cjs`、`check-browser.cjs`：localhost 无头表格验证真实 DOM 录制、定位、输入与刷新确认。
- `check-startup.cjs`：完整无头冷启动，延迟容器、目标标签、嵌套选中 class 及编辑控件，直到真实日期/文字锚点和空白格检查；不输入业务内容。
- `check-control-readiness.cjs`：延迟渲染、空地址、暂时只读的恢复，以及永久缺失、重复匹配、登录/关闭时的停止与零业务输入。
- `check-selection.cjs`：当前 9 月录制未加载的 8 月，首次延迟切换、后续缓存切换、过渡期无选中标识、纯样式定位及超时停止，不输入业务数值。
- `check-ui.cjs`：正式 React 页面配模拟桥接验证完整操作及 1100px 布局。
- `check-login.cjs`：本地无头浏览器验证协议确认、二维码、手机确认/过期、匿名不误判、任务隔离、刷新、关闭与重试；不写业务数据。正式弹窗测试覆盖请求串行、StrictMode、延迟返回时取消及宿主协议链接。

Node 检查使用仓库现有 Playwright 依赖，不新增 npm 包。真实文档扫码、无头登录复用、在线保存及 Windows 注册/准点执行仍由用户在 Development 验收；本地替身通过不代表外部服务验收完成。
