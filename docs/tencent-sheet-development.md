# 腾讯文档填报（Development）

入口：自动化任务 → 新建任务 → 腾讯文档填报。此入口仅在 Development 注册，Production 的桥接调用也会拒绝访问。

## 使用

1. 在自动化任务列表打开独立的“网页适配配置”，录制 Sheet 标签、单元格名称框和内容编辑区／公式栏。测试通过后保存，多份文档复用。旧适配若只有前两项，需要补录编辑区。
2. 新建腾讯文档任务时选择已保存适配并填写文档链接。打开文档、扫码登录后，选择实际工作表；“记住网页当前工作表”会显示已保存的名称，示范位置时也会自动记录当前工作表。
3. 新文档不预设业务。用户新增业务名称和可选单位，示范两个同月日期的填报格、日期格和固定文字标志，再确认第三个预测位置。保存位置后直接进入该字段的 Notion 绑定。
4. 选择现有 Notion 数据库、数值字段，以及业务日期范围或真实 View。日期模式支持当天、本月至业务当天、本年至业务当天；View 模式使用原 View 筛选，不叠加程序日期筛选。按原值求和，不自动换算单位。
5. 获取本次 Notion 数据，核对字段、数值、来源、范围和记录数，再检查网页位置并确认填写。默认业务日期为北京时间前一天，可指定补填日期。修改日期、字段、绑定或文档配置会使旧结果失效。

原任务已保存的位置及手动输入保留；此前新文档尚未示范的四项占位业务不会迁移为已配置字段。仍未开放定时运行。日期和固定文字锚点在每次填报时都必须验证通过，任何已有内容的目标格均停止填报。

## Notion 取数边界

- `TencentSheetNotionService` 复用现有 `IDatabaseQueryProvider` 和全局凭据，任务字段只保存数据库、字段及筛选引用，不新增 Token 配置。
- 一次获取中相同数据库、日期范围或 View 查询复用结果；数值字段支持 number 及实际返回数字的 formula/rollup。空记录、缺失或非数字数值均报错，不自动跳过或填 0；实际数值 0 可用。
- 取数快照绑定任务、完整配置及业务日期，5 分钟有效；失败重取会废弃旧快照。检查和填报从后端快照读取数值，不信任客户端改写的取数值。网页写入仍另需 2 分钟的一次性检查凭据。
- 自定义字段须先完成位置示范，再保存数据绑定。字段使用稳定 id，显示名和单位不参与定位；删除字段同时删除对应规则。

## 网页适配与文档配置分离

- `tencent-site-profiles.json` 独立保存网站级适配：名称、站点类型、候选控件定位规则和测试用文档地址。站点第一版为腾讯文档，不预设用户网页的 class、月份名称或 DOM 层级。
- 文档任务只保存 `siteProfileId` 引用，URL、工作表名称/月份规则、各业务位置示范和日期/文字锚点仍归各自文档。执行时从本地适配库解析当前版本，不信任请求附带的适配快照；更新共享适配不会修改业务位置规则。
- `site-adapter.cjs` 内的 `ElementPicker` 注入悬停高亮和阻止点击原操作的录制模式；`ElementAnalyzer` 采集标签、id、class、role、aria-label、placeholder、文字及父级/兄弟/层级特征；`LocatorBuilder` 生成运行时消费的候选规则。没有按录制结果生成固定业务代码，也不保存鼠标坐标或第几个元素。
- Sheet 录制先从一个成员向父级寻找共同结构的兄弟，使用共同 class，允许成员存在额外 class，并验证生成的集合规则不会纳入其他节点。录制阶段只保存集合，不强制存在 ARIA 或特定名称的状态类。测试阶段在两个唯一名称的标签间切换并切回，比较自身及子元素的 class、ARIA/data 属性和常用计算样式；只有三次采样都随选中项唯一转移的规则才保存。鼠标移开并清除焦点后再采样，避免把悬停/焦点误认为选中。运行时限定集合后精确匹配目标文本，不使用包含匹配；月份变化或顺序变化无需重录。
- 名称框优先使用稳定 id、aria-label、role/name、placeholder，再尝试稳定 class、测试标识和可唯一定位的父子结构。候选逐个验证可见、唯一、可编辑及地址形态；不使用坐标或位置序号兜底。没有可靠候选时要求重新录制，不能保存猜测结果。
- 支持可见 iframe 内录制；框架本身须有唯一的稳定 id/name/title/src 标识。Sheet 录制要求能辨认同类兄弟；选中状态无法通过切换验证时单独报错并阻止保存；虚拟化后尚未出现在 DOM 中的目标标签需要先在网页中展开或滚动显示。
- 保存前先通过标签切换学习选中状态，再验证 6 项：找到集合、按录制样本文字切换 Sheet、找到唯一名称框、输入 J9 并回车、离开输入框后重新读取地址为 J9、检查编辑区与名称框不同且聚焦后地址和内容保持一致。不向业务单元格输入数值。此测试证明公共控件可用，不替代业务锚点和写入前校验。
- 保存凭据由 worker 在测试成功后生成，绑定配置、目标适配 id/版本和测试 URL，10 分钟有效且一次消费。修改配置、测试失败或执行其他文档操作后不能沿用旧凭据；保存时再次检查控件可定位。并发更新共享配置时拒绝覆盖新版本。
- 登录提示不需要录制。定位/编辑前后检查可见 dialog、modal、遮罩或登录 iframe 中的登录/扫码提示，返回 `LoginRequired` 并要求扫码。保存状态继续沿用正式写入路径的状态检测及刷新回读。
- 网页适配录制三个公共控件，内容编辑区同样使用用户录制的规则；旧适配缺少编辑区时提示补录。适配测试不输入业务值，不代表已验证任意编辑器的真实提交和在线保存能力。
- 新任务设置 `requireTeaching`，必须完成各业务的位置示范才可检查和填报，不把旧表的默认行列套入新文档。既有任务的示范/兼容流程保留。

## 规则模板示范

- 每个自定义字段独立保存规则，可在同一工作表中横向、纵向混用。
- 两个示范日期可以不相邻；程序按日期差计算每天的整数步长。支持向右一列、多列，或向下一行、多行；同格、斜向、反向、跨月示范及非整数步长会被拒绝。
- 日期格按与目标相同的步长移动。记录第一天日期格后，程序读取第二个日期和第三个预测日期验证格式及位置，不猜测附近非空格。项目名称、公司或材料表头是固定地址的文字标志。
- 第三个预测位置会在网页中选中。用户点击“位置正确，保存此项目”后才持久化规则；当前选区不同、日期或文字发生变化时不会保存。取消或失败保留原配置。
- 示范会话绑定任务、配置和随机令牌，有效期 10 分钟。任何示范操作都会使旧填报预览失效，示范中禁止从界面执行填报。已保存规则随任务 JSON 持久化，重新打开后仍可使用。
- 中文月份工作表沿用按业务月份切换；没有年月命名的工作表使用固定名称。固定工作表若日期只显示日号或月日，规则只适用于已示范年月，跨月需重新确认；完整年月日表头仍会在每次执行时核对。
- 行列边界、实际业务日期的字段地址冲突和非空目标仍会阻止写入。不支持插小计、跳过周末等不规则排列。

## 边界

- `TencentSheetTaskHandler` 接入现有 `IAutomationTaskHandler`，拥有配置和记录；通用任务运行器不重试整个填报。
- `TencentSheetService` 使用持续的标准输入输出子进程通信，不开放本机 HTTP 端口。任务配置和浏览器会话位于 Development 数据目录，与 Demo、Production 分开。
- `TencentDocsBrowser` 拥有专用 Edge 会话；`TencentSheetClient` 借用页面，负责定位、读写和保存确认。关闭或取消后不会自动重新打开文档执行写入。
- 写入顺序保留已验证路径：名称框定位 → 读原内容 → 聚焦内容编辑区 → 再核对地址和空值 → 输入数字 → 核对输入 → Enter → 离开后重新读取。没有 F2、Tab、方向键探测、清空或覆盖。
- 所有非空目标（包括 0 和相同数字）均为冲突。预览确认绑定完整配置、日期和数值，有效期 2 分钟且只能消费一次。
- 原模板入库日期按合并单元格左上角读取，型材、板材共享 `{sectionColumn}24`。示范模式记录用户实际选中的日期格；多个单元格范围会被拒绝，不会搜索相邻非空格替代。
- 保存状态从可见状态提示读取；已存在的“已保存”不能证明本次成功。保存中时等待，保存错误立即停止；缺少状态过渡时采用延迟及刷新回读，最多三轮。任何数值输入后的错误均不重新写入，记录已提交和待确认地址。
- 读取阶段仅对明确的瞬态网络错误重试两次，间隔 1、2 秒；权限、登录、模板、配置、冲突和普通超时不重试。
- Playwright 复用已安装的版本，Development 发布时复制运行依赖；使用本机已有 Node.js 和 Edge。未新增 npm 依赖。

## 验证

- `scripts/verify.ps1 -SkipRestore`：前端测试、构建、.NET 测试和 Development 自包含发布，不同步 Production。
- `tests/tencent-sheet/check-browser.cjs`：独立的无头 localhost 表格，验证正式迁移后的定位、写入、冲突、保存失败；不访问真实文档。
- `tests/tencent-sheet/check-protocol.cjs`：文档域名、合并锚点和一次性确认绑定。
- `tests/tencent-sheet/check-rules.cjs`：横纵步长、跨月、闰日、边界、规则持久化及旧模板兼容；浏览器回归还覆盖真正的纵向填报和横纵混排。
- `tests/tencent-sheet/check-ui.cjs`：正式 React 路由的本地模拟桥接、无高级表单检查及 1100×700 布局；截图不证明外部文档成功。
- `tests/tencent-sheet/check-site-adapter.cjs`：不同 DOM 结构、非 ARIA 的选中 class、集合隔离、月份/顺序变化、候选回退、iframe、取消、登录提示和 J9 定位；业务内容不写入。
- `tests/tencent-sheet/check-site-protocol.cjs`：测试后保存凭据绑定、配置/地址/目标适配变化、失败重测和重复保存拒绝。
- 运行上述 Node 检查前，将 `NODE_PATH` 指向仓库现有 `tools/experiments/machining_summary/playwright_test/FineReportTest/node_modules`。

真实桌面扫码、共享文档权限和在线保存仍需用户在测试版验收。不要由自动检查启动用户桌面应用或访问用户文档。
