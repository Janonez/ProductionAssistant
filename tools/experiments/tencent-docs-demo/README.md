# 腾讯文档填报 Demo

这是独立实验应用，不接入正式 ProductionAssistant。支持本地模拟，以及通过本机 Playwright 服务操作真实网页。

**当前版本：F2 键盘写入 v4。** 旧路径曾出现目标 N9、实际改动日期格 N2 的问题。本版采用使用者实测的名称框定位 → 内容编辑区原值校验 → F2 进入编辑、确认空值、输入、Enter → 重新名称框定位回读流程；保留 F2，移除 Tab 和方向键往返。每个目标必须通过地址和原值检查，才能生成一次性填报确认。检查失败不会输入填报值。

企业微信页面的实际验收仍由使用者通过 Demo 完成。请关闭旧服务、重新运行 `start.cmd` 并刷新；右上角应显示「本机服务 · F2 键盘写入 v4」。新前端连接旧服务时会禁用写入。

## 启动与迁移已有配置

1. 双击本目录的 `start.cmd`，保持服务窗口运行。它只启动本机服务，不自动打开或操作网页。
2. 刷新原来的 `index.html` 页面。原浏览器 localStorage 中已保存的配置继续有效。
3. 点击「迁移当前配置到本地服务」。新页面在 `http://127.0.0.1:43128/` 打开并保存原设置。也可先导出 JSON，再在服务页面导入。
4. 后续直接使用该本机地址。关闭服务窗口可停止服务；在 Demo 中可单独关闭专用浏览器。

运行要求：Node.js 20+、Microsoft Edge 和 Playwright。当前仓库已有 Playwright，程序优先使用同目录依赖，然后复用 `tools/experiments/machining_summary/playwright_test/FineReportTest/node_modules/playwright`，本次不新增依赖。复制到其他电脑时需自行准备这些运行环境。

## 真实网页操作

1. 选择「真实网页」，在「环境与模板设置」保存文档地址及生产月报参数。
2. 点击「打开网页 / 扫码登录」，在程序创建的专用 Edge 中自行完成登录。
3. 在「网页操作设置」绑定名称框、值编辑区、工作表标签和当前工作表。默认「自动检查」不需要选择编辑状态或保存状态；程序检查输入框是否可编辑，提交后留出自动保存时间，再刷新回读。旧配置中的状态选择器保留，但自动模式不会使用它们。
   可点击「从网页选取」，再在专用浏览器中点击目标控件；选取仅记录控件，不执行原来的点击动作。若选到外框，程序只在其中有唯一可见输入框时自动定位到该输入框，否则会指出需要重选哪一项。Esc 或 60 秒超时会取消。
4. 如表格位于 iframe，先填写 iframe 选择器。可以通过「读取控件信息」查看当前页面各 frame 中的可见 DOM 控件。选择器也可以在应用内直接编辑。
5. 配置九个写前校验格：四个数据项的日期、下料与装焊公司、园区、型材及板材表头。日期列可以使用 `{cuttingColumn}` 等占位符；期望文本支持 `{date}`、`{company}`、`{park}`。
6. 保存设置后，点击「检查连接」。选择业务日期，在只读测试地址中填写本次目标（如 N9），点击「定位与编辑诊断（不写入）」。它会通过名称框定位、读取内容编辑区、按 F2 进入编辑后再次核对地址与原值，然后按 Esc 退出；不会输入测试数字。对四个目标分别确认后，再继续填报。读取或诊断单格无需填写四项数值。
7. 填写测试值，生成预览，再点「检查真实目标（只读）」。全量校验成功且无冲突后，点「确认真实填报…」，核对日期、工作表、地址与数值，再确认执行。

只允许空格填报；编辑区仅含换行、空格或零宽占位字符时按空值处理，不修改网页内容；任何已有内容（包括相同数字）均整批停止，不清空、不覆盖。全量检查包含九个锚点和四个目标格的名称框地址与内容原值检查；没有写前检查结果，服务端不会生成填报确认。确认两分钟内有效，只能提交一次；配置修改或浏览器重新打开后失效。执行前再次检查锚点与全部目标值，每格输入前重新验证地址与空值。完成后刷新网页并回读四个目标格，只有刷新回读一致才报告完成。

网页操作不是事务。中途失败会列出已经完成的格，以及可能写入但尚未确认的格；不会自动重试、自动覆盖或自动回滚。执行期间不要手动操作专用浏览器；需要中止时可以关闭该浏览器，应用会报告中断结果。

## 适配边界

当前实现按使用者实测流程操作：名称框输入 A1 后按 Enter，读取内容编辑区并比对预期；按 F2 进入单元格编辑器，再次检查地址与原值，确认仍为空后直接输入数值并按 Enter 提交，不执行清空操作。提交后重新通过名称框定位并回读，最终刷新验证保存。读取用的内容编辑区与 F2 激活的单元格编辑器分别处理；按 F2 后通过页面键盘逐字输入，不查找或聚焦 DOM 编辑器；是否实际写入由提交后的重新定位回读验证。值编辑区支持 `input`、`textarea` 或 `contenteditable`。工作表标签按完整名称匹配，不固定 URL 的 `tab` 参数。

地址回显和内容比对不是网页内部编辑目标的独立证明；该操作路径以使用者的页面实验为依据，本地模拟测试只验证程序流程。

「当前工作表」选择器必须随激活状态切换，不能固定指向一个月份。仅在网页确有稳定的状态元素时，才启用「额外检查网页状态标志」；此时「已保存」选择器必须只匹配保存完成状态，例如对动态文本补充 `:has-text("已保存")`。两种模式都保留刷新回读，等待一段时间或找到一个标志本身不会被认定为填报成功。

错误信息显示中文字段名与处理建议，可通过「前往相关设置」定位；底层日志仅在「技术详情」中展示。更新源码后需要关闭旧服务窗口、重新运行 `start.cmd` 并刷新 Demo，保存的配置和专用登录目录不会被清空。

企业微信共享表的真实读写适配尚未验收，本次未向用户共享表填报。实际控件、隐藏列、合并表头及会话有效期，需通过上述应用内流程确认。纯 Canvas 且没有可操作名称框 / 值编辑区的页面，需要额外专用适配；当前不会通过猜测坐标或调用网页私有接口绕过。

Notion 数据接入与定时任务不在本次手动 Demo 中。

## 数据与文件

- 本机配置：仓库 `artifacts/tencent-docs-demo/config.json`，由服务原子保存。原浏览器配置仍保留。
- 专用登录会话：`artifacts/tencent-docs-demo/edge-profile/`；不读取或共用日常 Edge 用户目录，不向前端返回 Cookie。
- 服务只监听 `127.0.0.1`。浏览器操作接口检查 Host、Origin 和本次服务启动生成的随机令牌。
- 源码：`core.js` 负责地址与模拟规则，`app.js` 负责界面，`server.cjs` 负责本机 API 与持久化，`browser.cjs` 负责真实网页操作。

## 验证

在本目录执行：

```powershell
node check.cjs
node check-service.cjs
node check-browser.cjs
```

前两项使用 Node.js 和仓库已安装的 jsdom 检查规则、交互、配置迁移、接口隔离、串行执行及部分失败报告。第三项只启动独立的无界面 Edge 与临时本地表格，使用没有标准输入框焦点、由表格处理键盘事件的模拟页面，验证诊断不写入、日期格不被修改，并检查完整应用到浏览器的实际 DOM 读写、九项锚点、冲突、重复提交、权限失败、未保存数据检测和刷新回读；不访问共享文档或日常浏览器。测试产物仅放在 `artifacts/`。
